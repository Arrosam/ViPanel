# 信任模型

## 一句话

**能打开 ViPanel 控制台的人，约等于能在这台机器上以 root 执行任意命令。**

装之前先接受这一条。它不是一个可以靠配置绕开的缺陷，是这个产品的定位决定的。

## 为什么是这样

ViPanel 的 agent（`claude`）由 `1panel-agent` 直接 `exec` 拉起，是它的直系子进程，
继承它的身份 —— 真实部署里是 root，跑在宿主机上。

**这是刻意的。** 上游 1Panel 的 Agents 功能把 agent 关在 Docker 里、靠
`docker exec` 打进去；那样的 agent 看不见宿主机的文件系统、systemd、docker、网络，
能做的只剩挂载进去的那一小块 —— 那不是管服务器，是管一个容器。

ViPanel 要做的是**服务器管理面板**，agent 是管理服务器的方式。所以它不能被沙箱困住。

代价就是本文开头那句话。

## 唯一的护栏：权限代理

没有沙箱兜底，所以工具调用的确认是唯一边界：

- claude 每次调工具前经过 PreToolUse hook，hook 阻塞等面板上的人做决定
- hook 只走本机 unix socket。走 TCP 的话，任何本地进程都能替你做安全决定
- 面板决定超时 120 秒，**远小于** claude 侧 600 秒 —— 那一层超时是 **fail-OPEN**
  （到点直接放行），必须抢在它之前给出明确答复
- 联系不上面板时降级为 `ask`（退回终端让人在那边确认），**不是** `allow`
- hook 可执行体缺失时，控制台顶部会显式标红「权限代理未生效」

`matcher` 用 `*` 拦所有工具，不做白名单：没有沙箱时，部分拦截等于给自己留一堆
想不到的口子。**已实测**它确实拦得住 MCP 工具（`mcp__vipanel__*`）。

## 面板操作能力（MCP）

开启后，agent 除了能操作这台机器，还能操作**面板本身**：建站、装应用、改防火墙、
删数据库。这不改变上面那句话的信任模型（它本来就是 root），但改变了两件事：

- **出错的方式变了。** 一条 `rm` 打错路径，影响面是文件系统；一次 `website_delete`
  打错 id，影响面是面板记录 + nginx 配置 + 证书 + 数据库，而且是一次调用完成的。
  所以卡片上显示的是「删除网站 example.com，同时删除数据库和备份」这样一句人话，
  不是 JSON —— 人看不懂就会一路点允许，那时权限代理是摆设不是护栏。
- **多了一层「谁能用」的限制。** MCP 不开端口，只走已有的 root-only unix socket，
  并且要求连进来的进程是面板自己 spawn 的会话的**后代**。你自己在终端里跑的
  `claude` 会读到同一份配置，但连不上。

三档确认：只读在板块授权后直接放行，变更弹卡片，删除类弹卡片 + 红色横幅 + 双击确认。
板块授权只在本会话内有效，不跨会话记忆。

**agent 不能碰自己的护栏**：`/ai/console/**` 整块被硬排除在工具目录之外，
生成器和运行时各拦一道。否则它可以调用「批准权限请求」这个接口来批准自己的请求。

**钩子不在时 MCP 整体失效。** 每次面板操作在执行前都要能对上一条已解决的权限决定，
对不上就拒绝。删掉 `vipanel-hook` 的后果是「面板操作全部失败」，不是「面板操作全部放行」。

整个能力可以在控制台设置里一键关掉，关掉后 harness 配置里的那条会被删除，
新会话里一个 `mcp__vipanel__*` 都不剩。

## 部署建议

- **不要**把面板端口直接暴露到公网。放在 VPN、跳板机或反代加认证之后
- 面板账号密码和 SSH 密钥同等对待
- 多人共用时，记住权限代理只能确认「这次工具调用要不要执行」，
  **它不区分是谁在点** —— 面板本身的用户体系才管这个
