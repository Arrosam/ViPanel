# 信任模型

## 一句话

**能打开 ViPanel 控制台的人，约等于能在这台机器上以 root 执行任意命令。**

装之前先接受这一条。它不是一个可以靠配置绕开的缺陷，是这个产品的定位决定的。

## 为什么是这样

ViPanel 的 agent（`claude`）由 `1panel-agent` 直接 `exec` 拉起，是它的直系子进程，
继承它的身份 —— 真实部署里是 root，跑在宿主机上。

**这是刻意的。** 上游 1Panel 的 Agents 功能把 agent 关在 Docker 里、靠
`docker exec` 打进去；那样的 agent 看不见宿主机的文件系统、systemd、docker、网络，
能做的只剩挂载进去的那一小块 —— 那不是管服务器，是管一个容器。

ViPanel 要做的是**服务器管理面板**，agent 是管理服务器的方式。所以它不能被沙箱困住。

代价就是本文开头那句话。

## 唯一的护栏：权限代理

没有沙箱兜底，所以工具调用的确认是唯一边界：

- claude 每次调工具前经过 PreToolUse hook，hook 阻塞等面板上的人做决定
- hook 只走本机 unix socket。走 TCP 的话，任何本地进程都能替你做安全决定
- 面板决定超时 120 秒，**远小于** claude 侧 600 秒 —— 那一层超时是 **fail-OPEN**
  （到点直接放行），必须抢在它之前给出明确答复
- 联系不上面板时降级为 `ask`（退回终端让人在那边确认），**不是** `allow`
- hook 可执行体缺失时，控制台顶部会显式标红「权限代理未生效」

`matcher` 用 `*` 拦所有工具，不做白名单：没有沙箱时，部分拦截等于给自己留一堆
想不到的口子。

## 部署建议

- **不要**把面板端口直接暴露到公网。放在 VPN、跳板机或反代加认证之后
- 面板账号密码和 SSH 密钥同等对待
- 多人共用时，记住权限代理只能确认「这次工具调用要不要执行」，
  **它不区分是谁在点** —— 面板本身的用户体系才管这个
